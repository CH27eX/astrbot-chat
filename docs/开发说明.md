# AstrBot Chat（Pocket）

本地优先、可迁移到云端的 AstrBot WebChat 客户端。PC 与手机共用一套代码，
通过本机 BFF 访问 AstrBot，API Key 不会进入浏览器。

## 快速开始

> 只想安装使用：看 `docs/安装配置指南-0.2.26.md`（Windows / Linux / Android / iOS 的安装与首次配置）。
> 想改代码 / 自己出包：看 `docs/从源码构建.md`。

1. 确保 AstrBot（Launcher 启动）正在运行。
2. 复制环境变量模板并填入 API Key：

   ```powershell
   Copy-Item .env.example .env.local
   # 编辑 .env.local，填 ASTRBOT_API_KEY
   ```

3. 安装依赖并启动：

   ```powershell
   pnpm install
   pnpm dev
   ```

4. 打开 <http://127.0.0.1:5173>。

> `.env.local` 已在 `.gitignore`（`*.local`）里，不会进仓库。

## 双击启动（推荐）

桌面上的 **「AstrBot Chat」** 快捷方式，或项目里的 `启动 AstrBot Chat.cmd`。

它会按顺序做：

1. 检查 AstrBot 是否在运行；没运行就启动 Launcher，并等它就绪（最多 180 秒）；
2. 启动 BFF（`8788`），等待健康检查通过；
3. 检查 `dist` 是否过期，必要时自动 `vite build`；
4. 启动 PWA 服务（`4173`），用 Edge/Chrome 的 `--app` 模式打开独立窗口。

停止：双击 `停止 AstrBot Chat.cmd`，只停 BFF 和 PWA 服务，**不会关闭 AstrBot**。

日志在 `logs/`：`launcher.log`、`bff.out.log`、`bff.err.log`、
`preview.out.log`、`preview.err.log`、`build.log`。

注意：

- 首次使用需要先 `pnpm install`；
- 脚本优先找 PATH 里的 `node`，找不到会回退到 DSH 自带的 Node；
- 如果 AstrBot 启动器已经打开、但实例没启动，脚本会等 180 秒后提示你
  先在启动器里点「启动实例」。

## PWA 安装

Service Worker 只在生产构建注册。要测试安装：

```powershell
pnpm build
pnpm preview
```

打开 <http://localhost:4173>：

- **电脑**：地址栏右侧出现安装图标，或菜单里的「安装 AstrBot Chat」。
- **安卓**：Chrome 菜单 →「添加到主屏幕 / 安装应用」。

要求：**HTTPS 或 localhost**。手机通过局域网 `http://10.x.x.x:5173` 打开时，
浏览器不会给安装入口，也不会允许录音；上云 + HTTPS 后自动可用。

Service Worker 只缓存应用外壳和静态资源，`/astrbot/` 下的 API 永不缓存。

## 主动消息

页面打开时，每 10 秒拉一次当前会话的历史：

- 发现新消息 → 直接追加到消息流，不用刷新；
- 页面隐藏、且开启了「主动消息通知」→ 弹系统通知，点击回到窗口；
- 页面切回前台时立即补拉一次。

触发方式有两种：

1. **设置 →「测试主动消息」**：立即向当前会话发一条测试消息；
2. **AstrBot WebUI → 未来任务**：投递地选当前 WebChat 会话
   （UMO 形如 `webchat:FriendMessage:webchat!astrbot!<session_id>`）。

限制：**关掉页面后收不到**。PWA 的 Web Push 在国内依赖 FCM，不可靠；
要“关掉也能收到”，需要再接一条外部通道（企业微信 Webhook / ntfy / Telegram 等）。

## 端口自动发现

AstrBot Launcher 每次启动都会通过 `DASHBOARD_PORT` 环境变量换一个端口
（历史出现过 17853 / 16537 / 15090 / 19869 / 18395）。

BFF 的处理顺序：

1. 若 `.env.local` 的 `ASTRBOT_BASE_URL` 可用，直接用；
2. 否则找到运行 `...\core\main.py` 的 python 进程；
3. 枚举它的监听端口，逐个探测 `/api/v1/auth/setup-status`；
4. 命中后缓存，失败时重新发现。

所以通常**不需要手填端口**。

## 已知边界

- **改 `server/index.mjs` 需要重启 BFF**：`pnpm dev` 会同时重启 BFF 和 Vite；
  只改前端时 Vite 会热更新。
- **username 必须与身份桥一致**：默认 `astrbot`，对应
  `webchat:astrbot = <显示名>:FriendMessage:<QQ号>`（填你自己的）。改了就不会共享记忆。
- **历史消息只读 `platform_message_history`**：按 `session_id` 查。
  QQ 侧的原话不会变成气泡（和面板的限制一样），但她的上下文里有。
- **API Key 权限**：`chat` + `file` 足够聊天；读会话详情需要更高权限，
  所以历史走 BFF 直读 SQLite，不依赖那个接口。
- **测试会话**：`1c2f25b7`、`81aaf5dd`、`509542d6` 是联调产生的，
  可在面板「对话管理」里删，或之后用带 `data` scope 的 Key 清理。
